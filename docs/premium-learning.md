# German Quiz local development record

## Baseline, before UI and engine edits

React 19, TypeScript and Vite build a static Arabic RTL app with isolated German text. App.tsx owns the shell, hash navigation, unified import and legacy quiz. UnifiedPractice.tsx manages setup, chapter lessons, attempt sessions, settings and study progress. StudyExercise.tsx renders and grades the study activities. The original practice catalog builds vocabulary facts from the verified repository-independent data. The study engine uses validated structured answers and source references.

The current educational package is german-quiz-education version 1. It wraps vocabulary versions 1/2 and study version 1. Import parses the local file, validates both datasets and builds a usable catalog before committing one IndexedDB record (education) in german-quiz-study version 1. Without that record, the app reads the old vocabulary active record in german-quiz-personal and the separate study pack. progress, practice-plan and practice-position are separate keys. LocalStorage contains theme, practice preferences and the legacy vocabulary attempt. The old quiz attempt has question/choice IDs but no answer dates. The existing study event history records dated scored activity, self-assessed flashcards and completed writing, but lacks the learner’s submitted text.

Settings downloads the education package and a separate progress backup. Old progress backups are version 1. Review scheduling is derived from timestamped events, so preserving identifiers and stored events is essential. GitHub Pages is a static, manual deployment workflow, with a public build allowlist and content-free checkout guard.

Baseline on codex/premium-learning at 8a04d46: 80 tests across 14 files passed with local private fixtures, along with the production build. No private files are in the branch. Tests include package fidelity, study grammar and grading, quiz filtering, real browser import, legacy upgrade and offline reload. Production assets are kept separate from the private educational inputs.

## Spaced learning rules

New wrong answers and missed flashcards are due six hours later. Historical mistakes retain their original immediate due date until a new attempt supplies evidence. The first correct retrieval starts a one-day interval, followed by intervals of 3, 7, 14 and 30 days. Once a retrieval sequence begins, an early correct answer stays in history without advancing its interval. A failure restarts the sequence and reopens a resolved item. Four successful retrievals since the last failure, each after the first at its due date or later, are needed for mastery and automatic mistake resolution. Flashcards use self-reported retrieval. Accuracy is restricted to objectively graded events. The mastery numerator is items at the fourth stage; its denominator is attempted distinct items. The displayed ratio requires at least three items with repeated evidence. Completed free-form writing stays in the progress archive and contributes neither graded accuracy nor mastery.

For a standard adaptive session, each ten selections aim for four due items, four unseen items and two weak items in the selected scope. If a category is empty, the remaining slots come from available categories, with recently seen or strong material used last. Within each category, repeated errors and time since exposure rank first, seeded variation breaks ties, and selected skills and chapters get preference among similarly ranked items. A mastered item can still appear when its review is due or when the learner chooses every eligible item. Recommendations modify the setup or offer a review action. They never start a session by themselves. Incorrect questions only reappear through a future or explicitly requested separate review session.

Difficulty adjusts the assistance, not an inferred level of the source exercise. Fewer than 50% correct across at least four recent graded attempts in that skill trims one distractor. Eight or more recent attempts, spanning at least a day and at least 83% correct, put recall first on supported formats. Learners can still switch modes. The engine does not infer grammatical or vocabulary facts beyond the validated local content.

## Storage and traceability

The education package and database schema are unchanged. New attempt evidence uses a version 2 marker and a stable session ID plus question index. The answer and its resume checkpoint commit together in one transaction. The version 2 progress export reads both version 1 and version 2 archives. Existing timestamps, identifiers and old saved data are retained. Legacy practice plans are copied into two new keys in one transaction. The active copy excludes free-form writing while the original plan and checkpoint are left in place. Old vocabulary attempts without dates remain accessible in their saved attempt view; no dated history is generated from them. The application uses the imported item or a stable reference to show source details, so unavailable educational content is identified as such in old mistake records.

## Local verification

From the branch checkout, run `npm run build`, then `npm run preview -- --host 127.0.0.1 --port 4180 --strictPort`. The preview opens at `http://127.0.0.1:4180/german-quiz/`. Browser storage is tied to the address. Use the existing private unified file from Settings if that preview origin has no library. Full-data browser tests take its local path as the argument to `npm run test:browser`. Browser captures can be written to a private folder outside the checkout using `GERMAN_QUIZ_PREMIUM_SCREENSHOTS`.
